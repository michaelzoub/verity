# Verity architecture (v1)

The canonical flow sources are the versioned Mermaid files beside this README; the SVGs are rendered review artifacts. Any interface change must update the diagrams, tests, contract ABI/address data, OpenAPI, and shared types in the same change.

Actors are Privy company authentication, the requester/company wallet, payout wallet or authenticated platform agent runtime, API, private Supabase Storage, Postgres queue, E2B grader worker, ChallengeFactory, per-challenge ChallengeEscrow, and indexer. The wallets, platform runtime, contract, and worker are trust boundaries: the worker never returns grader source or validation data; the contract accepts only EIP-712 results from the separate settlement signer and verifies immutable challenge terms.

On-chain state is the factory-to-escrow mapping, funded challenge terms, immutable requester and grader commitment, submission count, finalized submission hash, scaled integer score, payout, expiration, and refund events. Off-chain state is private grader source bytes, language/runtime/entrypoint/config, public challenge specifications and examples, score schema, solution bytes, authenticated platform traces, jobs, API authentication records, projections, and indexer checkpoints. Confirmed `ChallengeCreated`, `SubmissionFinalized`, and `ChallengeRefunded` events are projection sources of truth.

Invariants: grader source is private and committed deterministically over canonical source, language, runtime, entrypoint, config, and dependencies; challenge-defined score ranges are validated before settlement; scores are exactly scaled to Solidity `uint256` values; submissions are hashed before grading; nonce consumption, capacity checks, submission persistence, and job enqueue are atomic; worker outcomes are authenticated and job-bound; a database payout claim and on-chain replay guards prevent double payout; refund is possible only after the immutable deadline and only to the immutable requester; duplicate events do not duplicate projections. There is no mock provider mode.

Company authentication boundary: Privy access tokens are verified only by the API. A verified Privy subject resolves to a local company record and authorizes company-owned challenge and grader operations. Privy never signs settlement payloads, controls contract custody, determines payout recipients, or is available to the grader worker/indexer.
